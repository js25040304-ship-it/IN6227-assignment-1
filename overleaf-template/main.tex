\section*{DATA AND CLEANING}
The supplied archive contained one binary target, \texttt{label} (\texttt{no}/\texttt{yes}), and 15
predictors: 7 numeric and 8 categorical. Rows without a label cannot
supervise training, so they were excluded before modelling:
3 from the development split and
1 from the test split. That left
31,109 development rows and 13,333 test rows.

The positive class was 24.0\% of development rows and
23.8\% of test rows. A majority-to-minority ratio of
3.17:1 means a classifier can reach 76\% accuracy by
always answering \texttt{no}, so accuracy alone was never used to judge a
model. Missing predictors affected roughly 0.16\% of rows in the
development split, and neither split contained duplicate rows; no test row shared its complete predictor vector with a development row, so there was
no evidence of train/test row overlap, and the test split contained no unseen categories.

Distribution checks flagged 10,908 IQR-extreme
\emph{values} in development, but the flags are concentrated rather than diffuse:
\texttt{activity\_duration} (5,350) and \texttt{load\_ratio} (2,527) supply 72\% of them, which points to skewed distributions in two
variables rather than corrupted records. Test profiling flagged
4,762 values, a similar density (35.7 vs.\
35.1 flags per 100 rows), so the two splits behave comparably. No row was
deleted on outlier evidence: with a 3.17:1 imbalance, blanket deletion removes
minority-class examples the model needs most.

The strongest numeric correlations were \texttt{performance\_score} with \texttt{stability\_index} (0.891); \texttt{performance\_score} with \texttt{composite\_rank} (0.880); \texttt{stability\_index} with \texttt{composite\_rank} (0.830). Correlated inputs were retained for the tree model; logistic coefficients are not read as independent effects.

\section*{PREPROCESSING AND FEATURES}
Numeric predictors were median-imputed and categorical predictors
most-frequent-imputed, in both cases fitted inside the training part of each
fold so that no validation row influenced its own imputation. Categorical
levels were one-hot encoded with unseen-category handling, a minimum level
frequency of 2 and a cap of
100 levels per field. Only logistic regression used
numeric scaling. Every learned transformation stayed inside the
5 shuffled stratified folds (seed 42).

The aggregate-like predictor \texttt{composite\_rank} had uncertain prediction-time availability; this was a provenance risk, not proof of target leakage. A development-only sensitivity check changed macro-F1 by 0.0002 for logistic; -0.0011 for random forest when \texttt{composite\_rank} was removed.

The flagged aggregate was dropped before final evaluation, and the final pipelines
use the remaining 14 predictors. The check used development folds only and
cannot certify that the other fields are available at deployment.

\section*{TRAINING AND SELECTION}
Three configurations were compared on identical fixed folds: a
most-frequent dummy baseline, regularised logistic regression as an
interpretable linear reference, and a random forest as the nonlinear
challenger~[1]. The random forest was the sensible challenger because interactions
between the categorical and numeric predictors are plausible; a tree splits on them
directly, whereas the linear model must encode each interaction by hand.

The search space was fixed in advance. Logistic varied C (0.1, 1.0), class weight (balanced, none) (4 settings per feature set); Random forest varied class weight (balanced subsample, none), max depth (18, unlimited), min samples leaf (1, 3) across four coupled settings per feature set (not a full factorial; fixed at max features=sqrt, n estimators=160). Every candidate was fitted
with and without the excluded feature, giving 17 candidate configurations in
total and 85 fold fits. The selected settings were class weight=balanced subsample, max depth=unlimited, max features=sqrt, min samples leaf=3, n estimators=160. Search
stopped once that predefined grid had been evaluated once.

Macro-F1 was the primary selection metric because it weights the classes
equally and therefore cannot be improved by ignoring the minority
class~[3]. Selection used the paired development-fold difference with a
predefined one-standard-error practical-tie rule. Final-test metrics did not
inform any feature, parameter, threshold or model choice.

\section*{FINDINGS AND DISCUSSION}
The declared rule selected the random forest: macro-F1 was the primary
metric and the one-standard-error tie test was fixed before the final split was
read. The lead held out (0.770
versus 0.761 across folds;
0.769 versus 0.762 on test, balanced accuracy
0.800), and it was not free: the random forest
recovered 77.2\% of positive cases against
57.0\% for logistic (640 fewer false negatives, 953 more false positives), giving positive
precision 0.584 versus 0.696 and accuracy
0.815 versus 0.839. Per class it is better on \texttt{yes}
(F1 0.665 versus 0.627) and worse on
\texttt{no} (0.872 versus 0.897).

Ranking quality is a separate question from the decision rule. ROC-AUC was
0.889 for the selected model and 0.889 for the
reference, and average precision was 0.703 versus
0.702, so the two models order the held-out rows almost
identically; the visible difference comes from where each untuned decision point
falls, not from one model separating the classes better. Reporting only accuracy,
or only AUC, would have hidden that distinction.

Across paired folds the random forest-minus-logistic
macro-F1 difference was +0.0093 (SD
0.0111, SE 0.0050) and the
random forest won 4 of
5 folds. That clears the practical-tie rule, but the
rule is not a significance test: folds share training data and a one-point gain is
modest. Forest has the lower observed error cost only if a false negative costs more than $953/640\approx1.49$ times a false positive; this comparison is post hoc and explains the choice rather than driving it.

No threshold tuning was attempted: with no supplied error costs and an
already-inspected holdout, a cost-driven threshold chosen now would turn that
evidence into another tuning resource. The defensible next step is a fresh
development-only plan with the costs written down first; until then the
random forest is a reproducible research choice under macro-F1, not an
endorsed operational policy.

The analysis assumes independent rows and a stable train/test collection. No
dependency warning was raised, but that is not evidence of independence:
shared entities or a time order would need group- or time-aware validation.
The results also do not establish causal effects, fairness across unobserved
groups, probability calibration, or prediction-time availability for every
retained field, so generalization beyond this split remains conditional.

\section*{SKILL GENERALISATION}
The report is produced by a reusable SKILL driven by an AI operator. The
operator proposes preprocessing and model choices; a fixed policy then
constrains which candidate families and which selection rule may be used, so a
run cannot silently switch models to chase a score. The SKILL profiles the
data, records typed quality warnings, evaluates the surviving candidates in
fixed folds against a dummy baseline, and writes a run directory of
machine-readable artefacts from which the report is rendered.

Generality was exercised, not proven. 4 synthetic modelling cases
ran end to end on differently shaped inputs (numeric-only binary, mixed-type
three-class, missing values with an unseen category, imbalanced binary) and each
produced a two-page report; 4 unsafe or unresolvable inputs
returned an explicit request for human input or a typed refusal instead of a
fabricated result. This shows the pipeline runs on differently shaped inputs and
declines unsafe ones; it does not establish accuracy on new real data.

\section*{VERIFICATION}

candidate settings, saved predictions and package versions (python 3.13.4, pandas 2.2.3, numpy 2.5.3, openpyxl 3.1.5, scikit-learn 1.9.1~[2]), together
