## Borrowed foundations and adaptation rules

We may reuse public ideas, interfaces, and established practices, but the submitted implementation and reasoning must remain traceable.

| Foundation | What we adapt | What we must not do |
| --- | --- | --- |
| OpenAI skill-creator guidance | Concise entrypoint, progressive disclosure, deterministic scripts, validation, real-use iteration | Copy an unrelated skill and rename it without understanding or testing it |
| Public OpenAI skill examples | Trigger descriptions, hard boundaries, resource routing, observable validation | Copy source text without attribution or retain irrelevant constraints |
| scikit-learn Pipeline and ColumnTransformer | Leakage-safe mixed-type preprocessing and joint parameter tuning | Preprocess the full dataset before cross-validation |
| scikit-learn model-selection guidance | Stratified cross-validation, held-out evaluation, multiple metrics | Tune repeatedly against the final test set |
| MLflow tracking concepts | Run IDs, parameters, metrics, artifacts, timestamps | Add a heavy service dependency unless it materially improves the assignment |
| Supplied report template | Two-column structure, type hierarchy, compact in-text figures and tables | Keep outdated 2023 placeholders or shrink text to force the page limit |

Any copied code fragment must be license-compatible, attributed where required, understood, and covered by a relevant test. Prefer original glue code around stable library APIs.
